## 用户在工程里能做什么

从文件菜单新建节点工程，打开根图时可看到多轨、节拍编辑器、调音台和当前配置可用的设备端点。进入多轨或节拍节点可看到成员轨道；编辑音符、片段、节拍和混音参数时仍进入原有 LMMS 编辑器。节点仅描述端口与连接。音频处理沿用宿主内已有的乐器、效果、播放句柄、轨道总线和 Mixer，不引入第二个引擎、外部 DSP 进程或外部跳线服务。

| 对象 | 对外呈现 | 实际关联 |
|---|---|---|
| 多轨聚合 | 按成员能力暴露音频、MIDI 端口，可进入子图 | 映射 Song 的轨道。端口保留成员标识，使同组两轨能送往不同混音通道 |
| 节拍聚合 | 按成员能力暴露音频、MIDI 端口，可进入子图 | 映射 PatternStore 的成员轨。编排中的 PatternTrack 仍触发既有 Pattern 列，避免根图和子图重复触发 |
| 成员轨 | 乐器轨提供其可用的 MIDI 与音频端口；采样、人声轨按实际播放或录音能力呈现 | 挂接现有轨道实例。自动化轨保持参数控制语义；具有音频输出不意味着同时具有音频输入 |
| 调音台 | 初始一对 Master 立体声输入、输出端口。增删通道同步增删对应端口 | 图上端口指向现有 MixerChannel。通道接收、发送量、效果链、推子以及 Master 汇总沿用现有 Mixer |
| 最终音频与 MIDI I/O | 依全局设置选用的后端及其实际端点生成。设备输入在图上是信号源，设备输出是目的地 | MIDI 走已有 MidiPort/MidiClient，音频走已有输入或输出路径。默认 Master 至已配置的主音频输出。保存端点引用，设备设置仍由全局管理 |

## 连线和存档规则

- 新增可发声音轨默认连接 Master。轨道菜单改选混音通道时，图上更新同一条连接；图上改接时，播放目标和菜单随之更新。根图聚合端口与子图成员端口引用同一路由，一次连接只送一次信号。
- 显式断开后，播放可继续推进，但该连接不再投递信号。无连接和连接通道 0 必须可区分。重新在菜单选择 Master 应能恢复声音，包括原通道值已经是 0 的情形。现有 `mix_ch_t` 是无符号通道索引，不可把断线哨兵直接传给 Mixer。
- 音频、MIDI 分别检查类型、方向、目的端能力和重复连接。轨道到调音台的默认选路保留单目标语义；并行效果发送沿用 MixerRoute。通道间连接复用当前反馈环检查。若某个后端没有可用输入，图中不提供可连接的对应端口。
- 拟在现有工程 XML 中加入带版本的节点工作流数据。原有轨道、音符、片段、插件状态、混音发送各由现有对象保存一次。节点数据记录无法从这些对象推导的显式断线、端点映射、设备连接及布局。优先核验并复用已有稳定标识；名称和当前列表序号不足以充当跨保存身份。删除、重排、同名或复制轨道时，连接应随对应实例变化。
- 两种扩展名表达同一模式。前者写 XML，后者沿用 LMMS 的工程压缩机制；压缩不改变音频素材引用方式。普通工程保留原格式和默认行为。设备离线时保留可识别的原连接及不可用状态，避免重新打开后误接另一设备。

## 按依赖实施

| 阶段 | 工作范围 | 最小验收证据 |
|---|---|---|
| N1 工程与存储 | 核对已有草稿，接入新建、打开、另存为、最近工程、浏览器及恢复路径；确定版本字段、对象身份和节点数据边界 | 对同一小型工程写出两种格式并读取，对比轨道、模式、节点数据；核对压缩文件实际可解压，普通工程仍可读取。用数据层测试完成 |
| N2 内部路由 | 建立能力端口和聚合映射，将图操作、菜单操作映射到同一音频/MIDI 路由；接入 Master、动态混音通道和全局设备端点 | 已知音频信号仅到达目标通道，断开后该路静音，重接后恢复；已知 MIDI 事件仅送到所选接收端；验证聚合不重复投递、既有混音发送仍有效 |
| N3 节点编辑界面 | 核对 Penpot 的“节点图 · 夜航”和“节点图 · 多轨 DAW 子图”，记录端口布局、根图与子图导航、连接与断开操作。采用 LMMS 现有 Qt 组件和主题，接入原编辑器入口 | 原生 Windows 窗口核对两层布局；用同一工程完成手动改接、断开、菜单重接、增删通道，检查实际输出和视图同步。缺少适用设计的部分先确认布局 |
| N4 工程联验 | 汇合格式、路由和界面，验证双格式交换、设备能力变化及旧工程 | 用包含乐器、采样和 Pattern 的小工程验证节点连接和编辑内容在两种格式中一致；保存前后的目标通道、断线状态和 MIDI 目的地相同；记录实际验证范围 |

每阶段先针对业务差异建立快速用例，再实施和验证。通过后更新记录、检查差异，依仓库阶段规则提交并推送，再进入下一阶段。构建前检查同工程任务，按需使用原生 Windows 工具链和仓库前台进度脚本。GUI 验证使用真实 Windows Qt 窗口；人工试听、真实硬件或人工布局验收未执行时记录为 MANUAL/PENDING。生命周期测试标记 SKIPPED（用户禁止）。

## 实施前检查

1. 区分工作区已有格式草稿与正式实现，核对节点模式在模板、新建、恢复、另存为时的传递。
2. 查清所选音频后端可读输入及可送输出、MidiClient 端点枚举，以及 Mixer 通道输出的实际取样位置，形成“端口 → 源码入口 → 可验证信号”的对应表。对单一硬件立体声输出，新增 Mixer 通道不会派生额外物理输出。
3. 进入界面工作前重新验证 Penpot 可连接并读取目标画板。已有记录只确认两张画板的名称，详细布局尚待核对。

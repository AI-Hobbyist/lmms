## 后端现状与最小接入点

`src/core/AudioEngine.cpp` 的设备工厂列出以下实时后端。本机 `build/lmmsconfig.h` 启用了 JACK、PortAudio、SDL，另有 Dummy。具体驱动或宿主 API 由所选后端提供。

| 后端 | 当前代码行为 | 节点工程所需变化 |
|---|---|---|
| JACK | `AudioJack.cpp` 已注册音频输入、输出，回调将输入送入共用录音缓冲。另有按立体声注册的输出。 | 在现有客户端上逐声道注册节点总线，在同一处理周期读取和写回各端口。 |
| PortAudio | `AudioPortAudio.cpp` 分别协商输入输出通道，但 `processCallback` 忽略输入指针。 | 接入实际输入缓冲；根图固定展示成功打开的输入、输出通道。 |
| SDL | `AudioSdl.cpp` 分别打开播放、采集设备，采集回调调用 `pushInputFrames`。 | 节点路径按两端实际音频规格和各自通道步长读写；采集打开失败时只展示输出。 |
| ALSA、PulseAudio、sndio | 各自实现仅打开播放路径，分别为 `SND_PCM_STREAM_PLAYBACK`、`pa_stream_connect_playback`、`SIO_PLAY`。本机配置未启用。 | 对支持采集的设备，节点模式分别打开并协商采集流，再暴露固定输入；播放端按实际协商通道暴露。需对应平台验证。 |
| Dummy | 无外部设备。 | 硬件输入输出均为零。 |

## 图和信号的约定

- JACK 根图默认一个立体声输入总线和一个立体声输出总线，各对应两个 JACK 音频端口。根图可分别添加 JACK Audio 输入、输出和 JACK MIDI 输入、输出。音频布局以有序扬声器名称表定义，包含单声道、立体声、常规环绕及带高度声道的布局，最高 9.1.6（16 路）。例如 5.1.2 与 7.1 即使通道数相同也保留各自布局和声道顺序。默认总线复用现有主 I/O，避免主输出被写入两次。
- 其他后端根图按当前设备实际打开的通道创建固定端点，输入与输出分别计数。硬件输入在图内是信号源，硬件输出在图内是接收端。外部 MIDI 通过所选 MIDI 驱动的实际来源进入图，音频后端名称不决定非 JACK MIDI 设备列表。
- 根图源 → 多轨边界输入 → 指定音频轨或乐器轨。保存总线标识、方向、布局、声道及轨道端点标识，设备缺失时保留连线并显示离线。节点音频通道贯穿根图和多轨边界，录音轨可按所选布局接收整条总线或明确指定的单声道。单条 9.1.6 轨应能录制、保存并回放全部 16 路，沿调音台发送至主输出。
- 每个音频周期发布一次输入，各武装轨按同一块序号独立取样，避免先录的一轨消费另一轨的数据。多轨同时开始时用同一传输位置建立片段。MIDI 按来源和连线分发，保留通道、音符开关和块内时间位置，送入目标乐器及现有 MIDI 录制入口；避免同一事件同时经经典全局输入重复触发。

## 实施顺序与代码边界

1. **设备与周期数据。** 在 `src/core/audio/AudioDevice.cpp`、`src/core/AudioEngine.cpp` 和上表对应后端接入各方向的实际通道及块缓冲。节点专用描述与通道路由宜放入窄接口，保持现有经典渲染入口。JACK 用 `src/core/audio/AudioJack.cpp` 的客户端和回调，复用 `src/core/midi/MidiJack.cpp` 的事件读取逻辑；当前 MIDI 输出端口注册被注释，实施时补齐端口注册和带帧偏移写出。注册与内存分配在实时回调之外完成。
2. **图模型与根图。** 在 `src/core/Song.cpp` 及其节点工程序列化入口保存设备端点与路由；在 `src/gui/MainWindow.cpp` 的根图和多轨构图路径接入。现有 `include/NodeWorkflowInputs.h` 和多轨输入定义优先复用。旧节点工程无设备端点时创建默认总线；已有输入名称、连接和轨道标识继续沿用。经典工程继续走原有音频、MIDI 和录音逻辑。
3. **实际录制。** `src/tracks/SampleTrack.cpp` 创建录音句柄，`src/core/SampleRecordHandle.cpp::play` 目前直接读取全局 `inputBuffer()`。节点路径改为读取轨道已连接的输入并沿用片段写入逻辑。外部 MIDI 接入现有 MIDI 客户端与目标乐器轨事件路径，录制与监听共享来源选择。无连接时不回落到全局输入。
4. **工程转换。** 移除 `src/gui/MainWindow.cpp` 中节点转经典的操作、确认框及对应分支，移除 `include/Song.h` 和 `src/core/Song.cpp` 中的 `convertToClassicProject`。保留 `convertToNodeProject`、经典工程正常打开和保存。检查“另存为”的过滤器和底层保存格式，使改扩展名也不能隐式转换。更新 `tests/ui/UiBaselineCapture.cpp` 内对被移除 API 的两处直接调用。

## 定向验收

- JACK 从单声道、立体声到 9.1.6 逐路输入可区分信号，检查根图输出的方向、通道顺序和隔离；新工程默认恰有一对立体声总线。非 JACK 对照实际流的输入与输出数，覆盖输入和输出数量不同及只输出的设备。
- 同一录音区间将两个不同来源接到两条武装轨，检查片段起点、帧数和各轨波形；同时发送带不同来源与时间偏移的 MIDI 事件，核对目标轨音符与录制位置。JACK MIDI 输出从接收端核对事件。
- 核对节点路由序列化的标识与映射、经典到节点转换的结果，以及所有节点转经典入口已移除。人工设备验收按 MANUAL/PENDING 记录，生命周期测试 SKIPPED（用户禁止）。不涉及 VST 沙盒、调音台重构或经典模式功能扩展。

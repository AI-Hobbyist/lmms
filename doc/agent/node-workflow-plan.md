## 用户在工程里能做什么

从文件菜单新建节点工程，打开根图时可看到多轨、节拍编辑器、调音台和逻辑 I/O 节点。进入多轨或节拍节点可看到成员轨道；编辑音符、片段、节拍和混音参数时仍进入原有 LMMS 编辑器。音频处理沿用宿主内已有的乐器、效果、播放句柄、轨道总线和 Mixer。

节点工作区提供导入传统 LMMS 工程（.mmp 或 .mmpz）并转为节点工程的入口。沿用原生读取与旧版本升级，将原轨道、片段、插件状态、自动化、Pattern 编排及混音路由映射到节点图。逐声道从原路由建立连接。导入保留源工程的素材解析上下文，保存时另存为 .mmpn 或 .mmpnz，源文件不被覆盖。验收覆盖两种输入格式、相对素材路径、导入前后播放及混音一致性，以及节点工程重新打开。

将已有连线拖到画布空白处可断开该连接。可从线身拖动，非共享端点也可直接拖动。音频连接每次只影响被拖动的声道。

节点工作区启用时，侧边栏中 .mmp 和 .mmpz 文件的右键菜单提供「导入为节点工程」。以点击的文件作为导入源，直接进入现有另存流程。经典工作区和其他文件格式隐藏该菜单项。

### 子图边界端口模块

- 所有子图均可使用通用入口和出口模块。按实际信号接口自动生成所需模块，并可预留未连接端口供后续使用。子图内端口与父图上该子图节点的外部端口一一映射。覆盖音频、MIDI、步进事件、SVS 歌声事件等现有信号端口类型。每个音频声道使用独立端口和连线。Pattern 编排轨和自动化轨保持以名称呈现，Pattern 的音频由节拍子图的实际成员音源导出。
- 两类编辑器子图内，成员或效果模块连接到该图的输出模块。原生调音台位于父图。用户拖入子图的效果器留在原子图。边界输出在父图可接调音台或兼容的节点。经典工程导入以原有调音台去向建立默认外部连线，兼容已有节点工程的逐声道路由。
- 旧节点工程未保存效果器所属的编辑器子图。迁移时优先按可确定的既有路由归位，归属冲突或缺少路由时默认归到歌曲编辑器，并持久保存迁移结果。
- 边界模块与端口用持久的图和端口标识互相对应，名称随关联轨道或端口更新。图内和图外的连接分别可编辑及保存。任一层断开只停止该路径的对应声道，自动转换覆盖原路由和手工断开的既有状态。
- 乐器、采样和 SVS 等可进入的最深层音源子图提供新增节点入口。添加扩展节点前说明经典格式无法保存该层节点和路由，用户可取消或勾选「不再提示」。包含扩展节点的工程直接拒绝转换或导入为经典工程，并说明原因。
- 后续单独实现最深层音源子图内新增乐器实例，参照 Penpot「最深层乐器子图 · 多乐器同奏」。多个乐器可接收同一事件源实现同奏，每个实例使用独立的音频声道端口与路由。节点工程需保存各实例、连线与参数，沿用深层扩展节点的经典格式兼容规则。
- Penpot 的多轨定稿已包含「多轨 MIDI 入口」「多轨音频入口」与「多轨音频出口」，出口逐声道映射至上层。实现前核对 Pattern 与根图的对应端口。定向验证使用经典导入样例对照音频，验证各级逐声道断开、接回、改接兼容节点及工程保存。物理设备接入、录音和 MIDI 设备绑定仍由后续计划处理。
- 本轮 Windows Release 增量构建退出 0。当前根图实窗显示歌曲编辑器和 Pattern 的独立 L/R 输出接到原生调音台。根图定向用例覆盖逐声道断线、接回和工程保存，退出 0。经典工程导入及音频活动点用例的业务断言通过，测试进程停留在退出阶段。增量包 `build/packages/lmms-node-workflow-20261121-233108-win64.zip` 已通过 VerifyOnly。最终人工验收与生命周期测试均按用户要求跳过。

LMMS 启动时默认进入经典工作区。LMMS 文件菜单提供「工作区模式」子菜单。展开后显示互斥的「经典工作区」和「节点工作区」，当前模式带勾选标记。选择工作区时同时转换当前工程类型：经典转节点生成 .mmpn/.mmpnz，节点转经典生成 .mmp/.mmpz。转换沿用原生工程对象，双向另存并保留源工程。经典格式无法表达的逐声道路由、独立节点或端口状态须在转换前明确列出，用户取消时保留原工作区和工程类型。Penpot 参照「LMMS 菜单 · 工程模式切换」。切换时另存对话框应预选目标格式后缀。目标副本成功写入后才更新当前工程路径、类型、工作区和路由。取消、写入失败或选择源路径时保留原状态。联验应覆盖双向成功转换、取消与不可写目标，并比较源文件内容及可保真的立体声路由。

默认节点工程沿用普通「新建工程」的初始化入口及模板优先级。工厂默认模板采用 140 BPM、4/4，包含 TripleOscillator、采样轨、Pattern 0、自动化轨，以及节拍编辑器内的 Kicker；混音器起始只有 Master。初始节点与接线从这些轨道和既有路由生成。用户自定义默认模板仍按原入口规则生效。Penpot 参照「根图 · 默认 LMMS 工程」，N4 对照两种新建入口的初始轨道、参数和默认路由。

独立 Penpot 示例页「默认工程 · LMMS 布局与空白 SVS」（页面 ID `139e9e99-e79c-80ee-8008-fa5b240c8db6`）提供原生主窗口、原生节拍编辑器、根图、多轨、节拍、SVS 音源子图，以及 TripleOscillator 和 Kicker 的默认音源子图。默认乐器子图显示 MIDI 输入 → 空白钢琴窗 → 音源插件 → 轨道输出，L/R 各有独立端口和连线。主窗口的位置、尺寸和轨道顺序按默认模板与仓库原生截图核对。节拍编辑器默认收起，展开时为 Pattern 0、Kicker、16 个空步进。额外 SVS 轨仅用于本示例。工厂模板保持原轨道集合。

本计划覆盖逻辑 I/O 节点、入口数量、逐声道端口和图内映射，沿用 LMMS 已有的主输出路径。Penpot 上的外部设备与录音目标是拓扑示意。

## 插件节点与独立钢琴窗

新建乐器轨或 SVS 音源轨时，轨道子图默认内含四个节点，按「MIDI 输入 → 空白钢琴窗 → 音源插件 → 轨道输出」连接。乐器轨使用空白 MIDI 钢琴窗和乐器音源，SVS 轨使用空白 SVS 钢琴窗和 SVS 音源。两者的第一个连接都接收 MIDI，SVS 钢琴窗到音源插件使用专用歌声端口，将歌词、曲线和片段时序随歌声数据传递。插件到轨道输出按声道独立连接 L、R，与上层轨道端口逐一映射。钢琴窗编辑、插件状态与轨道播放共用现有对象；子图和上层图各自呈现同一路由。

SVS 钢琴窗的 MIDI 输入仅供外部 MIDI 设备录入音符。该输入在当前计划中作为逻辑端口展示，设备绑定及录入另立计划。已有歌声片段的播放和合成通过专用歌声事件链路，保留歌词、时序和曲线。

Penpot 的「节点 · 多轨子图」显示两类轨道的 MIDI 输入和进入子图的入口。「节点 · 乐器轨」与「节点 · SVS 人声轨」显示各自完整的四节点链路。N1 使用轨道的持久身份和子图内部角色标识默认节点，保存逐声道连接和显式断线；现有轨道、插件与片段序列化继续承载各自的内容。

在多轨编辑器时间线上，双击乐器轨或 SVS 轨的片段块，直接打开该块对应的 MIDI 或 SVS 钢琴窗。片段块使用同一份音符数据绘制预览，按片段内的时间、时值和音高排列；新增空白块初始显示空预览，钢琴窗增删或移动音符后更新对应块。进入轨道子图通过独立入口操作。Penpot 参照「节点 · 多轨子图」页面内的「多轨编辑器 · 片段音符预览」画板。

节点工作区保留歌曲编辑器工具栏的加轨操作及乐器浏览器的拖放入口。多轨子图随歌曲编辑器的轨道成员变化刷新，两处引用同一轨道实例。新增乐器轨或 SVS 轨时，子图使用该轨道的默认音源链路。

歌曲编辑器节点的多轨子图在「添加节点」中提供「添加采样子图」「添加乐器子图」「添加 SVS 子图」。分别创建原生歌曲编辑器中的采样轨、乐器轨和 SVS 轨，复用对应子图类型及既有轨道编辑入口；从任一侧编辑同一轨道。Penpot 参照「多轨子图 · 添加歌曲轨道」。

节点图的添加菜单列出 LMMS 已安装且当前宿主可加载的音频插件，包括原生乐器、效果器以及现有 VST 宿主支持的插件。选中后创建一个插件实例，由现有宿主管理其编辑窗口、参数和状态。端口依据实例能力生成，例如乐器接收音符并输出音频，效果器接收并输出音频；仅在宿主支持时提供额外事件或音频端口。

也可从现有插件浏览器把受支持的插件拖入节点画布，在落点创建插件节点并显示可用端口。拖入后的节点等待用户手动连接。音频逐声道接线，类型不匹配的端口拒绝连接。Penpot 参照「效果器插件 · 拖入后待接线」。N3 验收包含拖入乐器或效果器、手动接入兼容端口并核对图及声音路由。

| 独立模块 | 添加与编辑 | 示例连接 |
|---|---|---|
| 空白钢琴窗 | 可直接添加为节点，也可从多轨编辑器添加空白钢琴窗成员。初始音符为空，打开节点复用现有钢琴窗；用户可另选乐器 | 钢琴窗的 MIDI 输出 → 原生或 VST 乐器的 MIDI 输入 → 音频效果器 → 调音台 |
| 空白 SVS 钢琴窗 | 同样可独立添加或作为多轨成员，初始歌声片段为空，复用现有 SVS 钢琴窗编辑音符、歌词和歌声曲线 | SVS 钢琴窗的歌声数据输出 → 具有相应能力的 SVS 插件 → 音频输出至调音台 |

独立添加「步进音序器」「空白 MIDI 钢琴窗」或「空白 SVS 钢琴窗」时，只建立独立音序数据和相应事件输出。步进音序器初始是一列无乐器、无已激活步进的空白 Pattern；其余两种初始无音符。三种入口均不实例化或加载乐器、SVS 插件或默认声库，也不自动连到音源和混音器。用户添加兼容音源后手动连接。轨道子图内置链路继续按对应轨道模板生成。

Penpot 的「节点 · 空白 MIDI 钢琴窗」「节点 · 空白 SVS 钢琴窗」「节点 · 空白步进音序器」各提供一张「独立添加初始状态」画板。

这些独立模块的创建入口只在节点工作流工程中出现。普通工程中已有轨道打开各自钢琴窗的行为照旧。多轨成员及其子图节点引用同一份片段数据，编辑、播放和存档各处理一次。

SVS 连线暂定专用歌声事件端口。N2 先核对现有 SVSClip、SVSTrack 与插件渲染请求的数据契约，确定哪些信息需要连线传递、哪些继续由插件或轨道持有。验收至少覆盖音高与起止时间相同、歌词或曲线不同的两个片段，确认各自的歌声数据能到达所连的插件。若渲染接口按片段接收乐句，上游交付带时间映射的片段数据，沿用原有渲染调度。普通 MIDI 输入只接受可表达的 MIDI 事件；连线菜单按类型过滤，防止丢失歌声信息。

### 纳入各阶段的验收

- N1 在两种工程格式中保存轨道子图及其内部节点身份、插件标识与宿主状态、钢琴窗片段及端口连线；同一插件的两个实例可分别恢复参数。
- N2 用已安装的原生插件和受支持的 VST 核验事件输入、音频输出及效果器串联。SVS 核验歌声数据和渲染音频两段路径；断开上游后检验旧片段不会继续触发。
- N3 核对节点添加菜单与两种空白成员入口。分别双击多轨编辑器的乐器和 SVS 片段块，确认打开对应片段的钢琴窗；增删或移动音符后检查该块的音符预览。再通过独立入口进入两类轨道子图，核对各自的默认四节点链路及 L、R 连线。确认普通工程保留原编辑入口。
- N3 在节点工程里分别通过歌曲编辑器工具栏添加轨道、从乐器浏览器拖入乐器，确认多轨子图出现对应成员并能进入新增音源轨的默认子图。
- N3 从节拍编辑器添加成员轨后，节拍子图立即出现引用同一 PatternStore 轨道的节点。乐器成员可进入默认音源子图，节拍仍由现有 Pattern 列调度。
- N3 节拍子图主页显示成员与连线。进入节拍乐器成员的内部子图后，在连线网格之外、画布下方按当前 Pattern 内容显示编辑区。步进序列提供 Pattern 下拉与可直接编辑的步进音序器。音符序列提供 Pattern 下拉、「打开钢琴窗」按钮和该成员当前列的音符缩略图。按钮打开同一个片段。缩略图与多轨片段预览采用相同的时间、音高和时值语义，切换 Pattern 或编辑音符后刷新。音频成员省略编辑区。复用原生节拍编辑器的 PatternStore，切换列时刷新内容，接线按成员轨 UUID 保持。验收覆盖两列切换、步进编辑结果同步到原生节拍编辑器、音符按钮打开正确片段、缩略图随切换及编辑同步更新、音频成员与节拍子图主页无编辑区，以及接线保持。默认 Pattern 0 的 Kicker 子图显示 16 个未激活步进。
- 节拍乐器内部子图的网格外下栏采用单行布局，整栏高度不得超过歌曲编辑器一个轨道行，定稿参考为 31 px。步进序列直接复用原生 Pattern 编辑器的步进绘制和编辑逻辑。节点下栏和原生 Pattern 编辑器统一使用固定 19 px 扁平步进块、22 px 步距，步进数变化时保持宽度，超出视口时显示水平滚动条。音符序列在同一行显示钢琴窗入口及缩略图，内容超过视口时在缩略区内显示水平滚动条。
- 同一乐器实例可以支持步进事件与 MIDI 事件，两者保持独立的端口类型和接线状态。节拍乐器子图跟随所选 Pattern 的片段类型，只显示该子图类型使用的事件端口。步进模式在网格内显示步进音序器节点，其「步进事件」输出接乐器的同类型输入；事件端口独立于 MIDI，使用 Penpot Kicker 画板的青色。网格下方仍复用同一 Pattern 的单行步进控件。钢琴窗音符模式保留原 MIDI 路径。音源输出仍按 L、R 分开。
- 节拍子图的「添加节点」可直接添加步进子图、音符子图或音频子图。创建指定类型的成员，并使用各自的端口与编辑区。Penpot 参照「节拍子图 · 添加指定类型」。
- 节点本体的右键菜单提供「复制节点」「粘贴节点」「删除节点」。节点提供钢琴窗时同时显示「打开钢琴窗」，直接打开该节点对应的片段。复制与粘贴沿用原节点类型，为副本分配独立身份。粘贴应能在兼容画布的空白处使用。删除更新关联连线。固定工程入口和输出保留其必要性，对无法执行的操作禁用。端口右键继续用于连线操作。Penpot 参照「节拍子图 · 音符成员右键操作」。
- N3 新建 Pattern 后，多轨子图显示其歌曲编排轨节点。重复放置已有 Pattern 只增加时间线片段，复用同一编排轨节点。声音端口仍归节拍子图里的成员轨。
- 节拍成员的混音连接归属成员轨 UUID，由所有使用该轨的 Pattern 列共享。N4 用两列 Pattern 和两个混音目标验证列的调度与成员轨的输出各自正确。
- N4 分别从独立节点和多轨成员编辑片段，验证播放时序、改线和双格式存取后的一致性。

## 连线和存档规则

- 每个可用音频声道有独立端口，每条音频连线只承载一个声道。立体声分别显示 L、R 端口和两条线，物理设备按声道编号。轨道、聚合节点、插件、调音台和设备端点都按各自实际能力暴露声道。
- 多轨支持多个独立 MIDI 入口和多个单声道音频入口，上层端口与子图入口逐一映射。Penpot 示例画出 MIDI 1、MIDI 2 和音频 1～4。各入口有稳定身份，可分别连接、断开和保存映射。硬件接入及录音运行路径另立计划。
- 新增可发声音轨默认按声道连接 Master。轨道菜单改选混音通道时，图上更新对应的逐声道路由；图上改接时，播放目标和菜单随之更新。根图聚合端口与子图成员端口引用同一条声道路由，每个声道只投递一次。
- 每个声道可独立改接、断开和重接。只断开 L 时，R 的连线与投递保持不变。无连接和连接混音通道 0 必须可区分。重新在菜单选择 Master 应恢复该选择对应的默认声道连线，即使原混音通道值已经是 0。现有 `mix_ch_t` 是无符号通道索引，断线状态须单独保存。
- 音频、MIDI 分别检查类型、方向、目的端能力和重复连接。轨道到调音台的默认选路保留单目标语义；并行效果发送沿用 MixerRoute。通道间连接复用当前反馈环检查。若某个后端没有可用输入，图中不提供可连接的对应端口。
- 拟在现有工程 XML 中加入带版本的节点工作流数据。原有轨道、音符、片段、插件状态、混音发送各由现有对象保存一次。节点数据记录无法从这些对象推导的显式断线、逻辑端点映射及布局。优先核验并复用已有稳定标识；名称和当前列表序号不足以充当跨保存身份。删除、重排、同名或复制轨道时，连接应随对应实例变化。
- 两种扩展名表达同一模式。前者写 XML，后者沿用 LMMS 的工程压缩机制；压缩不改变音频素材引用方式。普通工程保留原格式和默认行为。

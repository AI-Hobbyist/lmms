# Agent 增量回滚与禁止工程重载实施计划书

日期：2026-11-17。状态：用户已授权持续执行；实施状态见 incremental-rollback-progress.md。

## 1. 目标与硬边界

按用户最新要求：**Agent 干脆不允许重载工程**，避免模型频繁主动重载，也避免失败和 dry-run 间接触发整体重建。保留工程编辑的原子回滚能力。

最终行为：

- Agent 成功编辑直接修改当前工程；失败时逆序恢复本次事务的局部变更；dry-run 计算结果后恢复局部变更。三者均不整体重载。
- Agent 不得调用新建、清空、载入、恢复整工程的入口，包括显式命令、脚本嵌套、组合命令及历史命令的间接路径。
- “请求批准”与“无需批准”均遵守限制；批准只授权允许的操作，不能解禁工程重载。不能仅靠 system prompt 约束。
- 用户通过 LMMS 原有界面新建、打开、清空、撤销/重做工程的正常行为保留。本任务不要求把整个 LMMS 的所有历史操作改成增量实现。
- 范围覆盖内置聊天及 MCP 暴露的 Agent 工具入口，复用现有 CommandBus、ToolRegistry 和 ScriptRunner；不维护两套编辑工具。普通内部调用与 Agent 调用的边界必须显式区分，并由程序入口设置，不能接受模型传入的来源/绕过参数。

“不整体重载”指执行过程中不调用 Song::loadProject、createNewProject、createNewProjectFromTemplate、clearProject、restoreProjectState 或等效的整工程替换路径；不得通过重新创建所有轨道来伪装成局部恢复。受影响对象的局部替换允许，但无关对象、工程身份和主界面必须保留。

不包含：界面重新设计、插件架构重构、全面重做用户手动撤销系统、工程格式升级、无关性能优化及前次分析中的进度计数缺陷。

## 2. 当前实现依据

本计划依据当前源码与已完成的闪退分析，不把现有快照回滚当作增量回滚：

| 位置 | 当前行为 | 本任务要求 |
| --- | --- | --- |
| include/agent/CommandBus.h | 描述 mutability、TxScope、handler、preflight | 增加必要的执行限制与回滚能力声明，默认不信任未声明的写操作 |
| src/agent/CommandBus.cpp | beginBatch 进入 ProjectJournal 快照事务；失败 rollbackBatch；dry-run endBatch(false) | Agent 路径选择局部增量事务；所有失败分支统一回滚，不得偷偷回退快照 |
| src/core/ProjectJournal.cpp | beginTransaction 保存整工程；rollbackTransaction 调 restoreProjectState；快照 undo/redo 同样整体恢复 | 复用历史栈和事务边界，增加增量记录类型；原用户历史兼容路径保留 |
| src/agent/ScriptRunner.cpp | 脚本共享批次，步骤调用 CommandBus；析构守卫清理失败批次 | 传播 Agent 限制，脚本中途失败及 dry-run 走同一增量日志 |
| src/agent/ToolRegistry.cpp | 从命令描述生成目录 | 隐藏禁止的工程替换操作，并披露真实回滚/预演能力 |

已确认：普通成功写操作保存快照本身不重建；当前问题在失败恢复、预演、历史快照恢复及显式工程替换入口。前次视图生命周期修复继续保留，不以本计划替代。

## 3. 方案选择

采用“现有命令处理器 + 事务内局部逆操作日志”，不启动第二套 LMMS，不复制完整工程用于预演，不取消原子事务。

单纯增加 preflight 不能覆盖执行中部分写入后失败；仅隐藏 load 命令不能阻止脚本或 rollback 间接恢复；仅禁用 dry-run 会削减已支持能力。因此这些均不能单独作为完成方案。

实施时先列出当前注册命令的完整清单，逐项标明只读、增量编辑、外部副作用、工程替换和历史操作，追踪组合命令到底层写入。不得按命令名前缀猜测安全性。具体接口名在第一阶段确定，不先搭建通用撤销框架。

## 4. Agent 禁止重载的执行规则

1. 在聊天和 MCP 的可信入口建立不可由参数覆盖的 Agent 执行上下文，嵌套 execute、脚本 call、组合命令自动继承。
2. 目录不公开工程替换命令；执行层再次拒绝显式构造的调用。已知至少包括 song.load、song.clearProject，以及第一阶段盘点发现的其他等效入口。
3. 失败返回稳定错误，例如 agent_project_reset_forbidden，包含禁止原因；不执行 handler，不修改工程，不要求用户批准后重试同一禁止操作。
4. 同一限制用于两种批准模式。旧工具调用、旧会话、直接 MCP tools/call、脚本字符串与嵌套调用不能绕过。
5. 在工程重置公共边界加入最小的 Agent 执行限制检查，拒绝前不得删除对象或发出“即将重置”通知；不是只在信号发出后尝试取消。具体检查方式须与现有返回类型相容。
6. 不跨网络等待或批准等待持有工程事务。执行局部事务期间阻止事件重入导致的其他写入，复用现有主线程及音频模型变更机制；不把用户的无关编辑纳入 Agent 回滚。
7. Agent history.undo/redo 只允许当前栈顶可安全增量恢复的记录；遇历史整工程快照，在修改历史栈前明确拒绝，不自动跳过、不调用用户 GUI 撤销来绕过。用户手动撤销仍使用原路径。

限制不会授权关闭用户正在运行的 LMMS，也不改变用户文件与会话数据。

## 5. 增量事务与原子性

### 5.1 写入与记录顺序

- 每个写操作在首次改变模型前完成参数/目标验证、局部旧状态捕获、逆操作存储及所需资源准备。日志分配失败发生在写入前。
- 记录必须覆盖 handler 内每个可能已发生的修改，包括 setter 触发的关联修改；不能只在 handler 成功返回后登记撤销。
- 成功步骤加入事务日志；失败/异常后逆序撤回已应用步骤，并恢复工程 modified 状态、事务深度及历史栈。不能把执行前序号当作稳定对象身份。
- 重放撤销时不再次生成撤销日志，不再调用可能联网、读文件或失败的正向 handler；新增对象失败时移除本次对象，删除对象时保留可重新挂回的对象及依赖。
- 原子性指命令/批次结束后的工程状态等价于执行前，且回滚期间音频与其他命令不能观察半恢复状态。进程终止、内存破坏与第三方插件崩溃不在可恢复事务保证内。

### 5.2 局部记录分类

| 编辑类型 | 增量恢复要求 |
| --- | --- |
| 名称、参数、位置、长度、静音等属性 | 保存原值，通过现有模型接口恢复；同时覆盖实际关联字段 |
| 音符/SVS 数据/自动化点 | 保存受影响集合及稳定身份、顺序、连接；只恢复该局部数据，不重载工程 |
| 创建轨道、片段、效果等对象 | 日志持有新对象身份；失败逆序拆除，恢复容器顺序与关联登记 |
| 删除对象 | 提交前延迟最终销毁，保留对象、原父容器、插入位置和连接；回滚挂回原对象。提交与历史淘汰时清理所有权 |
| 重排、路由、连接 | 保存原顺序与引用关系，恢复双向关联，校验未影响对象身份不变 |
| 乐器/预设/插件状态替换 | 在可行的最小对象范围预先准备新状态，保留旧实例或可可靠恢复的旧状态；失败不靠重新读原预设文件补救 |

不得假定对象 XML 能完整还原运行中插件实例。对预设加载等已知失败路径，必须证明旧实例/局部状态可恢复，再允许真实写入；若现有对象生命周期不支持可逆挂接，先评估最小必要改动，超出范围则请求批准，不顺带重写插件体系。

### 5.3 批次与 dry-run

- 批次成功形成一个用户可撤销的增量记录；内部嵌套成功记录归入父事务，父事务失败撤回全部已写入步骤。
- 保持已有失败导致整批回滚的语义，包括未知命令、schema/preflight 失败、脚本断言失败及异常；不能只撤销最后一步。
- dry-run 对可逆命令使用真实执行加局部回滚，继续复用既有 diff/result 格式；不提交历史、不清 redo、不改变 modified 状态，不保留临时对象或插件窗口。
- 活动批次内 dry-run 使用局部保存点，成功预演只撤回预演部分；预演失败的整批终止规则按第一阶段核对的现有契约实现并测试，不能任意改变。
- 不在每次回滚调用 Song::restoreProjectState，也不保留“增量失败则自动全量恢复”的 fallback。开发中逆操作不完整是测试失败，不能将部分恢复报为成功。

### 5.4 历史及外部副作用

新增 Agent 编辑提交到 ProjectJournal 的增量历史记录中，undo/redo 复用其正反记录；保留原手动编辑记录和历史快照的读取兼容。干跑/失败不破坏用户原有 undo/redo。不要另建只供聊天使用的第二个历史栈。

搜索、下载、导出、配置、播放等不是工程原子事务。沿用现有独立操作边界，不宣称回滚工程会撤回文件/网络副作用；不允许把不可回滚外部副作用混入多步工程原子批次。其 dry-run 使用真正无副作用的预检/计划，不真的下载后再删除来伪装预演。禁止重载规则仍对这些入口生效。

迁移期间尚未具备可靠逆操作的写命令，Agent 必须在修改前明确拒绝，不允许退回整体快照；这只是阶段性保护，不能靠永久下架现有编辑工具宣称全部迁移完成。最终覆盖清单、确需另议的插件能力与所有行为差异必须单独列明。

## 6. 分阶段实施与检查点

各阶段按序完成自动验证、更新进度、审查 diff、提交推送并核对远端，再进入下一阶段。P1 的验证目标是确认旧实现的 RED，不将预期失败冒称产品通过；P2～P5 必须通过其对应 GREEN 验收。

| 阶段 | 交付内容 | 必须通过的自动验收 |
| --- | --- | --- |
| P1 边界盘点与 RED | 导出真实注册工具及嵌套调用矩阵；固定 Agent/手动入口边界、禁用操作清单、原子性和 dry-run 现有契约；编写失败用例 | 证明旧实现会在失败/dry-run触发重置；覆盖直接、脚本、组合及历史工具绕过路径；失败应来自目标行为 |
| P2 增量事务基础与硬限制 | 最小日志、保存点、所有权与增量历史记录；可信上下文传播；工程重置命令及公共边界保护；先接入简单属性编辑 | 成功、部分写入失败、异常、批次及 dry-run 原子恢复；工程重置计数为零；两种批准模式均不能重载 |
| P3 当前编辑命令迁移 | 按清单依次迁移属性/音符/自动化、创建删除、重排连接、乐器预设及 SVS/SVC 等实际暴露写操作；组合命令复用基础逆操作 | 各类别至少一个真实部分写入失败；关联数据恢复、对象身份/顺序及 Pattern 登记一致；预设失败不重载 |
| P4 脚本与历史集成 | 完整脚本批次、嵌套 call、diffPreview、Agent undo/redo；安全处理旧快照历史；迁移目录能力说明 | 后半脚本失败撤回前序步骤；嵌套预演与保存点、失败历史不污染；旧快照拒绝且无栈变化；用户手动历史仍可用 |
| P5 回归与交付 | 清单覆盖审计、既有 Agent/MCP 回归、真实窗口生命周期验证、开发构建与增量包、交接文档 | 所有当前允许的工具路径无隐式/显式工程重置；现有能力无未说明退化；ABI/依赖和包 VerifyOnly；无关文件无改动 |

P1 若发现完整原子恢复必须扩大生产模块范围，列出具体调用点、必要文件与取舍，先取得授权。不能在 P3 用“未来兼容”扩建通用框架。

## 7. 测试与完成标准

测试要验证真实效果，不只验证“某 helper 没被调用”：

1. 真实引擎及原生 Windows 主窗口，调用实际 CommandBus/ScriptRunner/聊天/MCP 入口；禁止 Qt offscreen。
2. 监测 projectAboutToReset/projectLoaded，并在所有整工程重建公共入口设置测试可观察断言；防止未发信号的隐藏恢复路径漏检。断言不能依赖仅搜索源码字符串。
3. 对未改对象保存 QPointer 和地址，回滚/dry-run 后仍存活且相同；比较实际属性、局部数据、轨道/片段顺序、路由、插件状态及工程序列化语义。仅 XML 相同不足以证明身份与运行状态未变。
4. 检查 modified、文件名、undo/redo 深度、事务深度、Pattern 登记、排队视图与延迟删除清理。新增/删除对象的所有权在回滚、提交、历史淘汰后均正确。
5. 实际 handler 写入后再失败，脚本第二/后续步骤失败、未知命令、预检失败、异常；验证整批恢复。配合窄范围故障注入验证每个已应用步骤，不在产品 UI 加测试专用行为。
6. dry-run 成功与失败、嵌套保存点、与历史已有 redo 共存、重复调用；预演结果仍正确，无网络/文件副作用。
7. 模型强行发 song.load/clear、脚本/组合/历史间接重载、两种批准模式、旧会话重放，均拒绝且零重置；用户手动打开/新建仍正常。
8. 原 Chat 11、MCP 5、命令 3 回归作为基础，按 P1 命令清单补充必要目标，不以旧 19/19 代替新需求验收。

最终 DONE：Agent 允许的工具调用、失败、dry-run、脚本和历史入口均无工程整体重载；原子回滚与预演结果通过上述真实路径验证；禁止的工程替换操作不可被批准或嵌套绕过；手动 GUI 工程操作保留。不得靠关闭全部写工具或取消 dry-run 通过验收。

人工安装后操作与真实第三方环境验收记录 MANUAL/PENDING，不阻塞自主工作，不记为 PASS。

## 8. 工程约束与交付物

- 实施前确认 Penpot 可连接，按原计划连接要求执行；本计划不新增布局，若确需改 UI，必须实时核对 Penpot，不脑补。
- 编译前确认同工程没有其他活动任务；使用现有 Windows 工具链，先加载 buildtools/Enter-LmmsEnvironment.ps1；优先 Python buildtools/build.py 进度脚本，jobs=2，复用 build/Release 及 plugins 目录。

- 交付：命令能力/覆盖矩阵、实现代码与必要回归、阶段进度和提交记录、增量包、更新后的 AGENT_HANDOFF.md。只完成本计划明确的 Agent 限制与增量回滚，不扩大为整个 DAW 撤销系统重写。

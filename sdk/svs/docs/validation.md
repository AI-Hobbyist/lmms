# Consistency checks and diagnostics

`SVSConformance <plugin library>` is a standalone C++17 tool. It loads through the public ABI, rejects an incompatible major/undersized table, checks catalog voice IDs and tested parameter Schema rules, exercises optional resource reads/ranges, submits at a nonzero clip position, checks finite stereo PCM, then checks release/resubmit/cancellation and optional progress/completion services. Full example string labels must survive JSON quoting and appear in feedback bound to the correct note. Each failed assertion prints `FAIL: <reason>` and returns 1. Normal output identifies voice/ABI and returns 0. The tool never loads LMMS or opens a GUI.

This is a fixture-oriented conformance probe, not exhaustive certification for every native engine. It expects audible synthesis for the catalog's default lyric and cancellation before render to be honored. It checks resource descriptor presence and bounded exact reads; actual SHA-256 verification is performed by LMMS's adapter. Conditional capabilities, complex pronunciation, dynamic curves, project persistence, race gates, theme and exports are tested by LMMS's integration suite. A successful probe does not imply complete real-language coverage or production model performance.

Host scanner diagnostics include invalid manifest/ABI major, architecture mismatch, platform mismatch, duplicate plugin ID, missing entry or incompatible C ABI, and invalid/empty voice catalog. Duplicate/missing voice IDs are rejected. Unknown parameters and rejected Schema values are preserved in project data with diagnostics; an invalid Schema does not enable controls or publish audio. A native fault cannot be isolated by an in-process scanner.

Errors use the codes in [api.md](api.md). Include `clipId`, `requestId`, and when relevant `noteId`, `parameterId`, `rangeId` in `error_json`. For build or probe failure, inspect the foreground `build.log` before continuing. Keep the first failed evidence and save the subsequent passing log under a distinct name. Do not increase timeout or silently drop a failed case to claim acceptance.

Development fault controls in SVSExample are for host integration tests only. Refer to its capabilities query context and existing LMMS tests for delay, cancellation-late-return, forced failure and invalid Schema fixtures. Ship normal settings and offline package resources; do not depend on local singer/avatar fixtures, reference directories, or installed TuneLab.

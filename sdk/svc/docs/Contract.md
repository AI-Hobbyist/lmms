# SVC ABI / host contract 1.0

ABI version `0x00010000`, capability schema version 1, segmentation algorithm version 1. Structures begin with their size; shorter layouts and unknown ABI versions are rejected. Append-only fields within a version may be ignored by older implementations. Engine/model/speaker/parameter IDs are stable UTF-8 strings. A saved ID is never a UI row number.

The public boundary uses fixed-width integers, pointer/length pairs, opaque jobs and function pointers. Host input buffers and callback payloads are borrowed for the duration of the call. A consumer copies audio before returning. Start copies the request and selection JSON, retaining the callback/user and input reader until destroy. Those user contexts must outlive the job. Start emits no events. Pump performs bounded work on a worker; host serializes pump and cancel. No callback may destroy/reenter its job or parser. Returning nonzero cancels. Cancel is idempotent; no further input reads or callbacks follow a cancelled pump. Destroy stops work and releases it before returning. Adapters using threads must join them at destroy. Exceptions must not cross the C boundary.

Input reads are at most 64 KiB. Stream feed calls accept at most 64 KiB, headers at most 16 KiB, parts at most 8 MiB, boundaries at most 200 ASCII characters. The parser stores at most one part plus a feed fragment; audio is published immediately after a full validated body. `SVC_DONE` is provisional until `svc_stream_finish` validates closing boundary and EOF. Callers must never commit a cache on the callback alone. Failed/cancelled jobs are terminal. Error events preserve previously published audio but do not complete the request. Profile-specific cleanup validation is configured by the adapter.

Capability documents require `schema_version`, `engine_id`, `models`, `parameters`, and `limits`. Models have `id`, `name`, `speakers` (`id`/`name` objects). Parameters have stable `id`, `name`, `type` (`number`, `integer`, `enum`), `unit`, `scope`, `default`; numeric `minimum`/`maximum` are optional, `step` is positive if specified. Missing bounds are unbounded metadata, not arbitrary engine limits. Enums have `options` with `id`, `name`, boolean `available`, and a `reason` when unavailable. Optional `visible_when`/`enabled_when` contain declarative equality objects, never executable expressions. Limits are positive `max_upload_bytes`, `max_seconds`, `min_seconds`. Adapters normalize engine-specific metadata before validation. Frozen requests retain unsupported saved values for restoration but omit them from inference.

Algorithm 1 fixes 20 ms RMS windows, 10 ms hop, maximum per-channel RMS, epsilon 1e-12, inclusive silence comparison, and 100 ms minimum consecutive silent-frame coverage. Choose the midpoint of each interior maximal silence run; leading/trailing silence and an all-silent source do not add midpoint cuts and still follow the same length rule; use integer absolute source-sample coordinates. Shorter-than-minimum segments merge into a neighbor before forced splitting; silence and tail audio are never removed. Defaults are −70 dBFS / 30 s / 10 s. Silence range −120..0 dBFS in 1 dB steps; length values are finite and positive with millisecond resolution, forced length <= threshold. Backend duration/byte limits are checked separately, never silently changing the configuration.

Forced splits apply only to segments strictly longer than the threshold. A short final request is padded to the backend minimum and its effective range is retained. Frontend request seams use 10 ms source context and at most 5 ms equal-power smoothing, cropped to valid ranges; internal backend blocks are not crossfaded again. Map output offset/count by absolute time: `round(output_sample * source_rate / output_rate)` at each absolute boundary, with one source-sample rounding tolerance (plus one output sample converted to source units). Never accumulate rounded block lengths. Streaming resampling retains adjacent samples and absolute phase across blocks; discontinuities and total duration beyond this tolerance fail the segment.

Connection tokens are engine credentials, excluded from projects, cache metadata, log output and naming identity. Local test service currently requires none, so Authorization is omitted. Production deployments should require Bearer token authentication; persist credentials only in OS credential storage if enabled. The adapter owns redirects and must not forward credentials across origins.
